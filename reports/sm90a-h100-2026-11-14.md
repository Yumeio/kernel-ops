# Báo cáo benchmark H100 SM90a — 2026-11-14

Trạng thái: **dev-only, dirty diagnostic**. Đây là so sánh trên máy dev, không phải
registry evidence (`kops` JSON có `dirty=true` vì cây làm việc đang chứa thay đổi
chưa commit). Số third-party là so sánh, không phải evidence.

Phạm vi: cell SM90a mới (`gemm_wgmma_kernel`, `fp8_gemm_wgmma_kernel`,
`grouped_gemm_wgmma_kernel`) và toàn bộ 18 family benchmark hiện có.

## 0. TL;DR

- **BF16 dense 4096³: 571 TF (57,7 % peak), 8192³: 590 TF (59,6 %)** — so với
  `mma.sync` cũ (153 TF) là **3,7×**, so với cuBLAS cùng phiên (401 TF ở 4096³)
  là **1,42×**; tỉ lệ này dao động 1,3–1,8× giữa các phiên vì clock.
- **FP8 tensorwise fast 4096³: 985 TF (49,8 % peak)**, 6,1× so với `mma.sync`
  (162 TF) và 1,02× cuBLAS (969 TF).
- **FP8 rowwise fast 4096³: 927 TF (46,8 %)**, 1,16× cuBLAS.
- **FP8 blockwise promoted 4096³: 678 TF (34,3 %)**, UE8M0: **699 TF (35,3 %)**;
  không có anchor cuBLAS (torch không biểu diễn được block scale 128×128),
  DeepGEMM JIT fail ở 12 case dense blockwise.
- **Grouped wgmma** (contiguous + masked, bf16/fp16/FP8/UE8M0): bf16 250–300 TF
  (1,6–2,7× vòng lặp eager từng expert của PyTorch, 10× ở case 1 row/expert);
  FP8 410–480 TF (18–29× so với dequant+matmul eager). Masked chênh contiguous
  < 10 %. Spot check fp64 trên đúng các shape bench: 0 mismatch.
- `test_sm90` **PASS** (dense sweep, unaligned out, epilogue, graph replay,
  determinism, FP8 contracts + accumulation precision, grouped contiguous/masked
  bf16 & FP8 blockwise, grouped graph replay với rows/expert đổi giữa các lần
  replay). `test_gemm` PASS.
- Toàn suite: **777 case / 18 family** (64 case communication cần ≥2 GPU nên
  chưa đo), 602 case có reference, geomean best-ref/kops **2,00×**, 410 thắng /
  192 thua. Riêng so PyTorch eager/hf: **2,62×** trên 570 case (447 thắng /
  123 thua).
- GEMM sau nâng cấp: **300 case (298 chạy)**, 249 case có ref, geomean **2,15×**;
  so riêng DeepGEMM + llama.cpp + bnb thì **1,07×** trên 85 case; so PyTorch
  **2,50×** trên 249 case.

Cảnh báo clock: máy này không giữ clock ổn định. Anchor cuBLAS đo trong **cùng
chuỗi baseline** (sau ~600 case, cùng protocol flush) là **270–400 TF** cho BF16
(401 TF ở 4096³, 278 TF ở 8192³) và **~970 TF** cho FP8 `_scaled_mm`. Một spot
check ở process riêng, GPU nguội, cho BF16 8192³ = 3,098 ms ≈ 355 TF — tức
cuBLAS có thể nhanh hơn 20–30 % so với số baseline trong chuỗi. Vì vậy mọi tỉ lệ `kops/cuBLAS` dùng số baseline cùng
phiên; `% peak` dùng peak dense 989,4 TF (BF16) và 1 978,9 TF (FP8).

## 2. Cổng kiểm tra

```text
./build/bench-sm90a/kops_test_sm90   -> PASS
./build/bench-sm90a/kops_test_gemm   -> PASS
```

`test_sm90` phủ: dense sweep theo tile, out lệch alignment, dense epilogue,
graph capture/replay với A thay đổi tại chỗ, determinism (replay == eager),
FP8 tensorwise/rowwise/blockwise/UE8M0 + sai số tích luỹ so fp64, grouped
(contiguous + masked, bf16 + FP8 blockwise, group rỗng / lẻ tile / nhiều tile hơn
SM), grouped graph replay khi số row mỗi expert đổi giữa các replay.

Sai số tích luỹ FP8 đo được (rms sai số / rms kết quả): fast **3,1e-3** (max
3,1e-2) tại K=18432; promoted **1,06e-4** (max 3,9e-4).

Mutation test (`tools/dev/kops.py mutate gemm`) **chưa chạy trong báo cáo này**.

## 3. GEMM wgmma

300 case GEMM (298 chạy; 2 case `mma_sm120` bị loại vì cần SM120), trong đó 104 case
dense bf16/FP8 cũ + 68 case mới: 48 grouped, 8 fp16, 9 rowwise promoted,
6 blockwise UE8M0 (bớt 3 case blockwise 256-row không có body).

### 3.1 BF16 dense (best tile cho mỗi shape)

| shape | tile tốt nhất | kops TF | % peak | cuBLAS TF | kops/cuBLAS | DeepGEMM TF |
|---|---|---:|---:|---:|---:|---:|
| 256×4096×4096 | 64x128 c1x1 | 259 | 26,2 % | 272 | 0,95× | 286 |
| 1024×4096×4096 | 128x128 c1x1 | 505 | 51,0 % | 372 | 1,36× | 406 |
| 2048×2048×2048 | 256x128 c1x2 | 431 | 43,6 % | 430 | 1,00× | 413 |
| 4096×4096×4096 | 256x128 c1x1 | 571 | 57,7 % | 401 | 1,42× | 365 |
| 8192×8192×8192 | 128x256 c1x1 | 590 | 59,6 % | 278 | 2,12× | 293 |
| 16384×7168×2048 | 128x256 c1x2 | 569 | 57,6 % | 283 | 2,01× | 283 |

Từ M ≥ 1024 cell mới vượt cuBLAS; M = 256 còn thua nhẹ (0,95×) vì tile 64×128
không đủ wave cho 128/256-row. `c1x1` thắng phần lớn shape; 2048² là ngoại lệ
(`c1x2`). Tỉ lệ kops/cuBLAS dao động 1,3–1,8× ở 4096³ giữa các phiên vì clock
(kops tuyệt đối ổn định 565–575 TF).

### 3.2 FP16 dense

| shape | tile tốt nhất | kops TF | % peak | cuBLAS TF | kops/cuBLAS |
|---|---|---:|---:|---:|---:|
| 4096×4096×4096 | 256x128 c1x1 | 569 | 57,5 % | 287 | 1,98× |
| 16384×7168×2048 | 256x128 c1x1 | 554 | 56,0 % | 253 | 2,18× |

FP16 dùng chung cell với bf16 (`kFP16`), hiệu năng tương đương bf16.

### 3.3 FP8 (best tile mỗi M; 4096×4096)

| recipe | M=256 | M=1024 | M=4096 |
|---|---:|---:|---:|
| tensorwise fast | 370 TF / 0,80× | 897 TF / 1,05× | **985 TF / 1,02×** |
| tensorwise promoted | 276 TF / 0,60× | 672 TF / 0,81× | 831 TF / 0,84× |
| rowwise fast | 338 TF / 0,75× | 754 TF / 1,09× | **927 TF / 1,16×** |
| rowwise promoted | 329 TF / 0,90× | 681 TF / 1,03× | 822 TF / 1,03× |
| blockwise promoted (fp32 scales) | 315 TF | 571 TF | 678 TF |
| blockwise UE8M0 | 341 TF | 600 TF | **699 TF** |

(`TF / kops/cuBLAS`; blockwise không có anchor cuBLAS.) Fast-accum đạt 45–50 %
peak ở M lớn; promoted thấp hơn 15–20 % đúng như thiết kế (promote mỗi 128 K).
UE8M0 nhanh hơn bản fp32-scale khoảng 3 % ở 4096³ và 5 % ở 1024.

### 3.4 Grouped (contiguous; masked chênh < 10 %)

| dtype | G=8, R=1024, 4096² | G=32, R=4096, 2048² | G=128, R=100, 1024² |
|---|---|---|---|
| bf16 | 115 µs / 298 TF / **1,8×** | 131 µs / 263 TF / **2,5×** | 112 µs / **10,1×** |
| fp16 | 123 µs / 280 TF / **1,7×** | 128 µs / 269 TF / **2,7×** | 119 µs / **9,2×** |
| FP8 blockwise | 77 µs / 449 TF / **25,1×** | 83 µs / 415 TF / **24,5×** | 78 µs / **56,2×** |
| FP8 UE8M0 | 71 µs / 481 TF / **26,8×** | 78 µs / 442 TF / **28,4×** | 76 µs / **85,8×** |

(`ms / TF / kops so baseline`; baseline là vòng lặp eager từng expert của
PyTorch — `F.linear` cho 16-bit, dequant 1×128/128×128 rồi `F.linear` cho FP8.
G=128/R=100 là case 1 row/expert + group rỗng nên baseline bị launch-bound.)

- Grouped bf16/fp16 đạt 250–300 TF, FP8 410–480 TF — thấp hơn dense vì mỗi
  group chỉ 1–128 row và B phải đọc toàn bộ N×K cho mỗi group.
- Masked và contiguous chênh < 10 %; case G=128 (1 row/expert, 28 group rỗng)
  vẫn đúng số (spot check fp64 bên dưới) và chỉ launch-bound.
- Tile 64×128 thắng ở G=8, 128×128/128×256 thắng ở G=32; FP8 128×128 nhanh hơn
  64×128 15–35 % ở M lớn.

### 3.5 Trước / sau so với đường `mma.sync`

Hai cell cùng tồn tại trong binary: case `gemm.mma_*` chạy `mma.sync`, case
`gemm.wgmma.*` chạy cell mới. 4096³:

| đường | kops `mma.sync` | kops `wgmma` | tăng |
|---|---:|---:|---:|
| BF16 | 153 TF | 571 TF | 3,7× |
| FP8 tensorwise | 162 TF | 985 TF | 6,1× |
| FP8 rowwise | 160 TF | 927 TF | 5,8× |
| FP8 blockwise | 142 TF | 678 TF | 4,8× |

Đường mặc định (không có tactic `.wgmma.`) giữ nguyên `mma.sync`, nên không có
hồi quy cho các case cũ: `gemm.mma_bf16.*` vẫn 153–171 TF như trước.

### 3.6 Kiểm chứng số của grouped

Ngoài `test_sm90`, một spot check fp64 riêng (dev-only) đã chạy đúng các shape
bench: G8/R1024/4096², G32/R4096/2048², G128/R100/1024², cả contiguous và masked,
sample 2 row × 8 cột mỗi group (kể cả group 1 row và group rỗng) — **0 mismatch**
(ngưỡng 2 % tương đối). Vì vậy các cờ `over_peak` không còn xuất hiện: case
grouped trước đây từng bị parse sai `G` (`.g` khớp `.grouped`) và báo GB/s vượt
peak; lỗi đã sửa.

### 3.7 Còn thiếu

- Chưa có case bench cho **epilogue** của cell dense (bias/silu/rowscale) —
  `test_sm90` đã phủ số, nhưng chưa có số hiệu năng.
- Chưa có case grouped **graph replay** trong bench (chỉ có ở test).
- 2 case `mma_sm120` không chạy trên H100.

So riêng PyTorch: **2,62×** geomean trên 570 case (447 thắng / 123 thua).
GEMM so PyTorch: **2,50×** trên 249 case (nhờ baseline grouped là vòng lặp eager
từng expert, đúng thứ một Python side chạy hôm nay).

Các điểm yếu còn lại (không đổi so với báo cáo trước):

- `mla_decode` split=1 chậm 10–50× so với SDPA; bản `s8/s16/s32` đã 0,6–1,3×.
- Prefill attention (`merge.attention`) 0,45–0,70× so với SDPA.
- `state`: conv1d 0,29–0,41× (causal-conv1d), delta/lightning prefill 0,16–0,56×
  (FLA), selective_scan/SSD 0,25–0,44× (mamba_ssm).
- Norm 0,63–0,95× so với FlashInfer/vLLM/SGLang; quantize per-group/static
  0,26–0,55× so với vLLM; `act_and_mul` 0,60× so với vLLM.
- `sparse_mla` 0,22×, `sparse_topk` 0,18–0,28× so với torch reference.

## 6. Hạn chế

- Cây làm việc dirty; `gemm_wgmma.cu`/`sm90a_impl.cuh` đang staged. Số liệu chỉ
  đúng cho snapshot đã build, không phải cho commit `90a9e4e` thuần.
- Clock không ổn định; mọi so sánh phải đọc theo anchor cuBLAS cùng phiên.
- `llama.cpp` đo hot-L2 (flush một lần mỗi nhóm 20 launch) — chỉ so với kops
  `--flush-l2 0`.
- 2 case `mma_sm120` bị loại; 64 case communication chưa có số.
- Baseline grouped là vòng lặp eager từng expert (và dequant cho FP8), nên tỉ lệ
  2–29× (case 1 row/expert tới 86×) không phải so với grouped kernel của vLLM/
  SGLang; muốn so ở mức đó cần adapter grouped của thư viện.
- DeepGEMM JIT fail ở 12 case dense blockwise và skip toàn bộ grouped; cột
  DeepGEMM chỉ có bf16.

## 7. Tái lập

```bash
cmake --preset handoff-sm90a && cmake --build --preset handoff-sm90a

./build/handoff-sm90a/kops_test_sm90
./build/handoff-sm90a/benchmark/bench_gemm --only gemm.wgmma --rounds 3 --flush-l2 256

# Spot check fp64 cho grouped ở đúng shape bench (0 mismatch):
nvcc -std=c++17 -O2 -arch=sm_90a -I. tools/dev/check_grouped_spot.cu \
  build/bench-sm90a/libkops_cuda.a build/bench-sm90a/libkops_host.a \
  -lcudart -lcublas -lcuda -o /tmp/check_grouped && /tmp/check_grouped

python benchmark/compare/run_thirdparty.py --all --torch --torch-style both \
  --impl all --external auto --build-dir build/bench-sm90a \
  --rounds 3 --flush-l2 256 \
  --json-dir out/thirdparty/sm90a-h100-2026-11-14 --resume --skip mma_sm120
```

Artifacts: `out/thirdparty/sm90a-h100-2026-11-14/report.md` (coverage + per-case),
`report-all-kernels.md` (716 dòng case), `report-op-summary.md` (213 op),
`report-ops-by-family.md`, `kops/`, `torch/{hf,builtin}/`,
`thirdparty/<impl>/`, `external/<name>/`.
